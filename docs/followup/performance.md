# 성능 측정 — 2026-10-15

측정 대상은 기존 운영 사이트 `https://about.kancho.co/`의 `/about/`, `/portfolio/?file=intro4`와 최적화한 로컬 프로덕션 빌드다. 기존 운영 소스는 `323448cfefb2bb7298d465e2efb9d8bc9ecadb08`이다. 개발 서버 결과를 운영 성능으로 사용하지 않았다.

Lighthouse 13.5.0과 로컬 Google Chrome에서 데스크톱 프리셋/390×844 모바일을 각각 3회 측정했다. 매번 새 브라우저와 빈 캐시를 사용하며, 표는 중앙값이다. 자동 테스트나 빌드와 동시에 실행하지 않았다. `npm run perf:audit -- URL label`의 원본 JSON·개별 표본·중앙값은 커밋에서 제외한 `artifacts/performance/<label>/`에 저장한다.

## 추정 방식의 한계와 추가 실측

기본 Lighthouse는 실제 느린 네트워크가 아니라 수집한 요청·렌더링 관계를 Lantern으로 재계산한다. 로컬 WOFF2 변환 후 About 모바일 추정 LCP가 2.111초에서 10.354초로 증가했다. 하지만 관측 FCP/LCP는 67/105ms에서 45/55ms로 빨라졌다. OTF 요청은 관측 페인트 이후인 208~214ms에 끝나 그래프에서 제외됐고, 작은 WOFF2 요청은 19ms에 완료되어 높은 우선순위의 페인트 의존성으로 포함됐다. `font-display: swap`의 대체 글꼴 표시를 이 추정 그래프가 충분히 반영하지 못했다. 포트폴리오의 동일한 추정 결과도 19.583초였으므로 이를 숨기거나 운영 실측 개선으로 표현하지 않는다.

일회성 진단에서 `--throttling-method=devtools`로 실제 제한을 적용한 로컬 About 모바일은 FCP 1.440초, LCP 2.574초, CLS 0.044였다. 이 한 번의 결과는 최종 전후 중앙값과 분리한다. 첫 화면의 LCP 요소도 기존 푸터와 새 터미널 입력 안내로 달라졌으므로 동일한 요소의 로드 시간 비교는 아니다. 전체 폰트를 보존하고 `swap`을 유지한다. 점수를 위해 폰트 요청을 인위적으로 늦추지 않는다.

운영 전후는 기본 추정 결과와 `PERF_AUDIT_THROTTLING=devtools npm run perf:audit -- URL label`의 실제 제한 결과를 각각 같은 방식끼리 비교한다. 제한 방식이 서로 다른 수치를 직접 비교하지 않는다. 이는 실험실 측정이며 실제 사용자 Core Web Vitals 분포를 의미하지 않는다. 방법은 [Lighthouse throttling 문서](https://github.com/GoogleChrome/lighthouse/blob/main/docs/throttling.md), 추정 그래프 원리는 [Chromium Lantern 원본](https://github.com/ChromeDevTools/devtools-frontend/blob/main/front_end/models/trace/lantern/metrics/FirstContentfulPaint.ts)에 근거한다.

## 확인한 개선

- CSS에서 모바일 데스크톱 사이드바를 먼저 숨겨 React의 미디어 감지 전에도 본문 너비 390px를 보장한다. 지연 감지 회귀 테스트에서 수정 전 실패, 수정 후 통과를 확인했다. 로컬 About 모바일 CLS 중앙값은 0.320 → 0.029, 포트폴리오는 0.304 → 0.007이었다.
- 로컬 포트폴리오 이미지 전송량은 약 61kB(데스크톱)/105kB(모바일)다. 기존 운영 사이트에서는 약 2.59MB였다. 확대는 원본 이미지를 제공한다.
- 4개 전체 폰트는 원본 파일 6,318,784 → 3,226,812바이트(48.93% 감소)다. HTTP에서는 기존 OTF도 압축되어 전송되므로 파일 크기 감소율을 그대로 네트워크 감소율로 주장하지 않는다. 로컬 포트폴리오 폰트 전송량은 약 4.25 → 3.23MB, About은 2.11 → 1.60MB였다.
- 기존 운영 사이트의 잘못된 `format("otf")` 선언에서는 폰트 요청이 없었다. 따라서 새 버전의 정상적인 사용자 지정 폰트 비용을 기존 운영의 폰트 0바이트와 구분한다. 모든 한글·Notion 문자를 유지한 대가는 첫 방문 시 전체 폰트 다운로드이며, 더 작은 글자별 서브셋은 별도 최적화 여지다.
- 데모 총 용량은 334.85 → 9.48MB(97.17% 감소)다. 브라우저 검증에서 GIF 요청이 없고 재생 전 MP4 본문을 받지 않으며, 선택한 영상만 실제 재생되는 것을 확인했다.

포트폴리오 모바일의 실제 제한 LCP는 약 77% 감소했고, CLS도 개선됐다. About의 LCP는 비슷한 수준이며 폰트 교체가 포함된 화면 완성도 지표인 Speed Index와 점수는 소폭 악화됐다. 따라서 개선은 페이지·지표별로 판단해야 한다. 전체 글리프를 유지하는 현재 폰트 전략의 초기 비용은 남아 있다. 배포 후 포트폴리오 JS 전송은 약 150kB로 이전 약 181kB보다 줄었지만, 폰트 비용을 상쇄할 정도는 아니다. 다음 성능 작업에서는 전체 문자 대응을 보존하는 분할 서브셋/가변 폰트 전략을 검토할 수 있다. 지금 측정은 그런 추가 작업이 끝났다는 주장이 아니다.

외부 Notion/iframe 응답은 이 두 초기 화면에 포함되지 않는다. 글을 연 후의 외부 응답 지연은 해당 서비스 상태에 좌우되며, 별도의 공개 Notion 통합 검증과 오류·재시도 UI 검증으로 확인한다. 폰트·정적 파일과 Next 이미지의 캐시가 적용된 반복 방문은 이 빈 캐시 측정과 다르다.
